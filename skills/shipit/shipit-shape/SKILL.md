# Shape

Understand the idea before endorsing it. Ask only what changes the next step.

## Size the work

Infer the mode from Dan's request. Ask if the distinction would change the work.

- **Demo:** demonstrate one idea to an audience. Learning or teaching is a valid goal.
- **Small project:** solve a focused problem with a working first version.
- **Product:** support ongoing use, with more attention to users and operating costs.

Start small when the future is unclear. A project can grow without restarting the process.
For a YouTube demo that needs recording beats or a companion repo, use video-demo-design
when available. A simple technical demo can stay in this flow.

## Clarify what matters

- Restate the idea briefly and neutrally.
- Use what Dan already told you. Do not make him repeat settled choices.
- Ask about the intended user, the current workaround, or the first useful outcome
  only where an answer is missing and affects what to build.
- Stop asking once the first version and its boundaries are clear. There is no question quota.
- For a demo, the teaching point and a visible result may be enough.
- Save technical decisions for when they affect the next build step. Keep any preferences
  already supplied.

## Give a recommendation

Recommend building the idea, narrowing it, or setting it aside, with a concrete reason.
A useful personal tool does not need to become a business. A demo does not need repeat users.
If several ideas are mixed together, suggest the one that best serves the stated purpose.
Raise a concern clearly, then respect Dan's informed choice.

## Continue

If the request includes moving ahead, use shipit-mvp to record a short initial PRODUCT.md
and continue toward the first working result. Do not add a separate approval round.
If Dan only asked for feedback, return the recommendation and stop.

Keep the shaping result in the conversation unless it must survive a handoff.
An optional brief goes in .shipit/shape/brief.md. Once incorporated, PRODUCT.md holds
the current scope; the brief remains history and does not need to be kept in sync.

Use plain words and short instructions. No em dashes.
